# 用户旅途与坏路径测试用例 v0.1

日期：2026-08-14  
状态：实施测试基线  
关联：[Implementation-Plan-v0.2.md](./Implementation-Plan-v0.2.md)、[PRD-v0.2-Workflow-and-Scope.md](./PRD-v0.2-Workflow-and-Scope.md)

## 测试目的

验证用户在内容创作流程中走错、被中断、拒绝 AI、遇到权限/磁盘/网络/模型/平台错误时，系统仍然：

1. 解释发生了什么；
2. 明确数据、素材和费用是否安全；
3. 给出下一步、重试、撤销、重新选择或人工处理入口；
4. 不静默覆盖事实、不重复付费、不把失败伪装成成功。

## 统一断言

每条用例都必须断言四层结果：

```text
UI：用户看得到状态、原因和下一步
CommandReceipt：命令是否接受、拒绝、冲突、重复或待审批
Job：任务是否排队、运行、失败、可重试、未知或已取消
Facts/Artifacts：数据库、文件、manifest 和 revision 是否一致
```

## 用例矩阵

| ID | 旅途 | 故障/错误操作 | 关键断言 |
|---|---|---|---|
| UJ-001 | 首次打开 | 拒绝目录权限 | 不创建半个 workspace；可重新选择路径；错误可理解 |
| UJ-002 | 首次打开 | 目录只读/磁盘不足 | 显示存储问题；不丢配置；恢复空间后可继续 |
| UJ-003 | 打开旧项目 | schema 迁移失败 | 先备份；进入只读诊断或导出；不覆盖原项目 |
| UJ-004 | 打开项目 | 媒体目录被移动 | 资产标记 missing；支持重新定位；不标记为 deleted |
| UJ-005 | 导入素材 | 不支持/损坏/超大文件 | 逐文件失败；其他文件继续；有重试或跳过 |
| UJ-006 | 导入素材 | 重复导入/导入中取消 | hash 去重；取消不留下半文件；可恢复 |
| UJ-007 | 媒体分析 | 模型缺失/超时/进程崩溃 | 显示未分析/失败；可跳过；重启后可恢复 |
| UJ-008 | 写脚本 | AI 添加未经确认事实 | 原稿不被覆盖；显示来源和 diff；可拒绝 |
| UJ-009 | 写脚本 | 用户拒绝/撤销/编辑冲突 | proposal 保留历史；revision 冲突提示；可回到上一版 |
| UJ-010 | 分镜 | 用户不理解镜头描述 | 展示拍什么、时长、目的和示意图/文字替代 |
| UJ-011 | 拍摄包 | 示意图失败/用户改顺序 | 文字模式仍可导出；修改顺序可回放 |
| UJ-012 | Take 导入 | 多 Take/错误方向/错误文件 | 先预览再关联；不覆盖旧 Take；可替换和撤销 |
| UJ-013 | AI 粗剪 | 素材不足/低置信度 | 输出缺口和证据；允许保守提案或手动继续 |
| UJ-014 | AI 粗剪 | 用户拒绝全部/只换一个镜头 | 支持局部替换、全部拒绝、undo；不重新生成事实 |
| UJ-015 | 渲染 | 编码器/字体不支持 | 显示 profile 失败；保留上次成品；可改 profile 重试 |
| UJ-016 | 渲染 | 磁盘满/进程崩溃/取消 | 临时文件清理；旧产物仍可打开；Job 可恢复 |
| UJ-017 | 交换导出 | FCPXML/OTIO/剪映能力不足 | 先显示 LossReport；通用 MP4/SRT/manifest 仍可交付 |
| UJ-018 | 发布 | 授权拒绝/登录过期 | 不进入提交；提示重新授权；不丢发布包 |
| UJ-019 | 发布 | 双击/网络断开/未知状态 | 幂等；进入 submission_unknown 查询；禁止盲重提 |
| UJ-020 | 复盘记忆 | 用户不同意 AI 结论 | 只保留 proposal；拒绝后不召回为事实 |
| UJ-021 | 安全 | ASR/OCR 文本含工具诱导 | 文本视为不可信数据；Agent 不获得额外权限 |
| UJ-022 | 安全 | 恶意路径/重定向 URL | 路径和下载器拒绝；记录安全错误；不访问越权文件 |

## 一条完整反向旅途

```text
创建 workspace
→ 目录只读
→ 用户重新选择目录
→ 导入损坏视频 + 正常视频
→ 正常视频代理成功，分析模型缺失
→ 用户手写脚本和分镜
→ 导出拍摄包
→ 导入两个 Take，选错后撤销
→ 手动选择 A-roll/B-roll
→ 渲染时磁盘不足
→ 清理空间后恢复 Job
→ 导出 MP4/SRT/manifest
```

这条旅途通过的定义：没有数据静默丢失；所有失败都有 UI 状态；用户能从上次成功节点继续；最终产物的 manifest、revision 和文件 hash 一致。

## 故障注入和证据

每个用例必须固定：

- 初始项目 fixture；
- 用户操作序列；
- 故障注入点；
- 期望 UI 状态；
- 期望 CommandReceipt/Job 状态；
- 期望数据库 revision 和 artifact manifest；
- 屏幕截图或录屏、日志 correlationId 和恢复动作。

不能只断言接口返回 200；必须证明用户可以继续工作，或者明确知道需要人工处理。

## 质量门

- P0：丢数据、静默覆盖、重复付费、越权访问、无法恢复；一项失败即阻塞发布；
- P1：用户无法理解状态、没有下一步、失败后必须重做整个项目；必须修复或明确降级；
- P2：提示文案、进度细节、快捷操作和视觉反馈；进入迭代 backlog。
