# 技术完整方案编制计划

日期：2026-08-14  
状态：架构文档已完成；代码执行以 [Implementation-Plan-v0.2.md](../Implementation-Plan-v0.2.md) 为准

## 范围

- 冻结桌面端、语言、运行时、存储、媒体、模型、Provider、Agent、编辑器和导出技术栈；
- 给出进程边界、目录结构、数据库对象、任务状态、错误恢复和安全规则；
- 给出从本地媒体理解到对标分析、脚本、拍摄包、AI 粗剪、导出、发布和数据回流的施工顺序；
- 将现有 e-cut、Nomi、OpenChatCut、Palmier Pro 和 ChatCut 的可复用边界落到工程设计中。

## 不动项

- 不把抖音口播写死进底层领域模型；
- 不以剪映私有草稿格式作为事实源；
- 不让 renderer 直接读文件、拿密钥、写数据库或调用第三方 API；
- 不把模型推断写回 ASR/OCR/时间轴等事实字段；
- 不在本阶段实现手机/相机远程控制、数字人、音色克隆和大规模生成式 B-roll。

## 主要风险

- Electron 原生依赖、SQLite 和 FFmpeg 的跨平台打包；
- 本地 ASR/OCR 模型体积、许可证和运行时差异；
- 私有剪映草稿格式变化；
- Provider 异步任务、临时 URL、限流和重复付费；
- AI 结果质量不稳定但必须可追溯、可审阅、可恢复。

## 验收门

1. 技术方案能从一张架构图追溯到进程、包、数据表和命令；
2. 每个外部调用都有能力、状态、错误、成本和恢复边界；
3. 一份 `FrozenEditSpec` 可以在不调用模型的情况下编译、预览、渲染和导出；
4. 本地媒体、参考账号、选题、脚本、分镜、Take、素材、编辑、发布和复盘均有唯一事实源；
5. 开源许可证、密钥、隐私和第三方素材边界明确；
6. 施工阶段有明确产物和质量门，不把未实现能力写成已完成。

## 回滚

本次只新增技术方案文档和引用，不修改运行时代码。若技术基线调整，只需更新本方案、Provider/媒体交换契约和领域模型契约，并在决策记录中保留旧方案。
