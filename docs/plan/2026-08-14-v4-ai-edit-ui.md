# V4 AI 粗剪页面与真实 Take 闭环

日期：2026-08-14  
状态：已实现本地提案 + 人工审阅 + 导出；Provider-backed 提案待接入

## 用户旅途

```text
创作项目
  → 脚本/分镜
  → 生成拍摄包
  → 导入多个 Take
  → 选择 Take
  → AI 粗剪
  → 查看缺口/镜头理由/证据/置信度
  → 逐条采用或拒绝
  → 确认并导出 MP4 + SRT + manifest
```

## 实现边界

- `desktop:propose-edit` 从 SQLite 读取当前项目的 Script、Storyboard、ShootTask、Take 和 Artifact，不相信 renderer 传来的素材事实；
- 当前 proposer 是本地可审计 fallback：它不生成不存在的素材，只把选中的 Take 变成 `EditProposal`；没有选择的 Take 进入 `missing_material`；
- UI 允许逐条采用/拒绝，确认时所有未拒绝操作才会进入冻结；原始 Script、Storyboard 和 Take 不被覆盖；
- `desktop:render-edit` 在 main 重新校验 proposal、素材 hash、源片段时长、workspace 路径并执行 reference RenderIR；
- 输出成功后只显示 workspace-relative 文件，用户可从 UI 打开 MP4、SRT 和 manifest；
- proposal、FrozenEditSpec 和 render run 在 schema v4 引入并继续由当前 catalog 迁移保存（当前总 schema v6）；它们保留状态、hash 和 manifest 相对路径。下一步仍要把这些写入动作提升为统一的 `CommandReceipt`/Job 命令，补足跨进程恢复。

## 坏路径与恢复

| 情况 | UI 表现 | 数据规则 |
|---|---|---|
| 没有项目 | 空状态引导回创作项目 | 不发网络请求 |
| Take 未选择/时长或 Artifact 缺失 | “还缺这些镜头”列表 | 不生成伪素材，不写 FrozenEditSpec |
| 用户拒绝全部 | 禁止导出并提示至少采用一个镜头 | 原提案保留，用户可重新选择 |
| 素材在提案后发生变化 | main 返回 hash/素材事实错误 | 上一次导出不覆盖，重新分析或重新导入 |
| FFmpeg/磁盘失败 | 失败信息显示在导出动作附近 | 临时文件清理，旧成功产物保留 |

## UI 交互合同

- idle：显示“生成 AI 提案”；
- loading：按钮显示“分析中/导出中”，重复点击 disabled；
- success：显示镜头列表或可打开的输出文件；
- error：错误和恢复动作在当前工作区显示，不需要查看日志；
- keyboard：所有采用/拒绝/导出都是可聚焦 button，并使用 `aria-pressed` 表达状态；
- reduced motion：沿用全局 `prefers-reduced-motion` 规则；
- narrow content：镜头理由允许换行，证据不做 hover-only 展示。
