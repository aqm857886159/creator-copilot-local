# 本地内容创作助手 PRD v0.2：工作流与范围

版本：v0.2  
日期：2026-08-13  
状态：产品范围基线；技术落地以 [Technical-Complete-Solution-v0.1.md](./Technical-Complete-Solution-v0.1.md) 和 [Agent-Stack-CTO-Review-v0.1.md](./Agent-Stack-CTO-Review-v0.1.md) 为准

## 1. 产品判断

### 1.1 产品定位

这是一个本地优先的内容创作操作系统：AI 负责理解账号、内容、脚本、分镜和素材，系统负责把这些对象组织成可审阅、可修改、可导出的生产流程。

首个场景聚焦抖音真人深度口播，但底层不做成“口播剪辑器”。产品通过“通用内核 + 工作流包”扩展到访谈、测评、课程、播客切片和其他平台。

一句话：

> 帮创作者把一个观点，从选题变成有画面、有证据、可发布、可复盘的视频。

### 1.2 不做的事情

- 不与剪映竞争完整的模板、花字、音效和素材生态；
- 不把 AI 黑盒成片当作唯一结果；
- 不要求创作者学习一套复杂的内部剪辑格式；
- 不把电脑摄像头或手机相机当成必须由软件控制的设备；
- 不先做账号矩阵、团队协作、商业投放和复杂 CRM；
- 不把每个模型的独有参数直接暴露给用户；
- 不承诺未经真实导入验证的剪映私有草稿兼容性。

## 2. 首个完整工作流

第一条必须跑通的生产闭环是：

```text
观点/选题机会
  → ThoughtPlan 与脚本
  → 分镜
  → 手机可执行的拍摄包
  → 多条 Take 与已有素材导入/检索
  → AI 剪辑提案
  → 用户确认
  → MP4/SRT/通用交付包/FCPXML 或 OTIO
```

账号对标、热点、发布、平台数据回流和长期记忆属于同一产品内核，但不得阻断第一条本地口播生产闭环。

## 3. 用户与核心场景

### 3.1 第一用户

- 个人抖音口播创作者；
- 小型内容团队中的编导、主理人或剪辑人员；
- 有观点和知识积累，但画面单薄、素材难找、补拍不清楚的人；
- 已经使用剪映，希望提升创作前半段和素材组织效率的人。

### 3.2 典型用户任务

#### 任务 A：从一个模糊想法开始

用户说：“我想讲清楚为什么很多人学不会理财。”

系统应能结合账号定位、历史内容和公开对标样本，生成若干有证据来源的切入角度，而不是只生成十个标题。

验收：用户能在 3 分钟内选定一个方向，并看到这个方向的受众、观点、证据缺口和可视化机会。

#### 任务 B：把观点写成可拍的脚本

用户选择一个选题后，系统生成结构化脚本：开头、核心观点、论据、案例、反例、结论、CTA、预估时长和重点强调词。

验收：用户可以在文本编辑器中改写脚本，提词器视图与脚本保持同一版本，修改后预估时长和分镜关联会更新。

#### 任务 C：解决口播画面单薄

系统将脚本拆成镜头，并解释每个镜头的画面目的：解释、举证、转场、情绪、节奏重置或品牌识别。

每个镜头给出景别、构图、机位、建议时长、参考示意图、拍摄方式和素材来源。已有素材优先匹配；没有素材时生成补拍任务。

验收：用户不用猜“这里要拍什么”，可以逐镜完成拍摄任务，拍完导入后自动关联到对应镜头。

#### 任务 D：从素材库快速找到可用镜头

用户搜索：“找一个 3 秒以内、竖屏、手部翻书、适合放在举例前面的镜头。”

系统同时使用结构化标签、转写、时间区间和语义检索，返回候选镜头、匹配原因、可用区间和权属状态。

验收：用户可以在 30 秒内从候选中选中镜头，并能看到它为什么匹配以及是否存在权属风险。

#### 任务 E：生成可审阅的 AI 粗剪

系统根据冻结脚本、分镜和用户选中的素材生成剪辑提案，不直接覆盖项目。提案包含主口播轨、B-roll、字幕、基础文本、音乐/音效、节奏调整和每个决策的依据。

验收：用户能逐项接受、拒绝、替换或撤销建议，并导出 MP4、字幕和 manifest。

## 4. 产品工作区

用户界面只保留四个主工作区：

1. **研究**：自己的账号、对标账号、热点、参考内容和机会卡；
2. **创作**：选题、资料、脚本、提词器和分镜；
3. **制作**：拍摄任务、素材库、AI 粗剪、时间线和导出；
4. **复盘**：发布物、数据快照、实验对比和记忆建议。

Provider 设置、任务中心、素材索引和账号连接器是全局能力，不单独拆成互相割裂的主流程。

## 5. 功能范围

### 5.1 P0：首条本地闭环必须具备

#### 项目与创作对象

- 创建项目、设置平台、画幅、语言、目标时长和内容支柱；
- 保存项目版本、当前阶段、下一步动作和关联对象；
- 项目文件可迁移、可备份，不包含供应商 key。

#### 选题和脚本

- 手动创建选题；
- AI 生成切入角度、观点结构和脚本草案；
- 从创作者本人选定的历史视频、稿件、笔记和自由表达中建立版本化 `VoiceProfile`，同时记录其常用论证方式、案例偏好和表达边界；
- 先生成可确认的 `ThoughtPlan`（核心判断、推理链、证据、反例和不确定性），再生成正文，避免用通用流畅度替代创作者的真实思考；
- 结构化脚本编辑；
- 预估时长、重点词、段落和提词器视图；
- 对草案独立执行 `VoiceRender`、`SpokenEdit` 和 `AuthenticityPass`，分别检查“像不像本人”“说起来顺不顺”和“是否有模板化 AI 味”；
- 支持并排查看原稿、AI 建议和用户修改，用户可指定“更像平时表达”“更口语”“保留停顿”“不要替我下结论”等偏好；
- 所有 AI 输出可编辑、可重生成、可标记为采用或拒绝。

脚本生成不是一个“去 AI 味”按钮，而是一条可追溯的个性化表达管线：用户先确认素材样本和思路，AI 再生成草案，最后由用户审阅后才进入分镜。系统不得靠随机错别字、无意义口头禅或故意降低信息密度来伪造真人感，也不得擅自补写个人经历、资历、事实或立场。

#### 分镜和拍摄任务

- 从脚本生成分镜；
- 每镜关联台词、目的、景别、构图、动作、时长和素材需求；
- 生成示意图或文字指导；
- 标记“已有素材”“需要补拍”“允许图形/生成素材”；
- 导出手机可打开的只读拍摄包，至少支持 HTML/二维码/图片清单中的一种；
- 同一任务允许录制多个 Take，并记录候选、采用、拒绝和重拍原因；
- 导入拍摄后按任务标识、文件、时间和用户选择关联到镜头。

#### 素材库

- 导入视频、图片、音频和文档；
- 生成文件 hash、代理、缩略图、波形和技术探针；
- ASR、OCR、镜头切分和基础标签；
- 自然语言搜索 + 结构化过滤；
- 人工修改标签、权属和可用区间；
- 资产与项目、脚本、分镜、成片建立关系。

#### AI 粗剪

- 根据冻结分镜召回素材；
- 生成 `EditProposal`；
- 预览差异；
- 用户接受、拒绝、替换和撤销；
- 生成字幕；
- 输出 MP4、SRT/VTT、RenderManifest 和通用媒体交付包。

### 5.2 P1：增强闭环和外部协作

- TikHub 对标账号、作品、热点和指标快照；
- 账号定位和内容支柱的版本化分析；
- FCPXML/OTIO 导出；
- 剪映/CapCut 私有草稿适配器的首个受限实验版本，必须输出应用版本、能力覆盖和 LossReport；
- 发布记录、数据快照和复盘建议；
- APIMart 图片/视频异步生成；
- 本地 Ollama、Whisper、ComfyUI 等 Provider；
- 自定义输出分辨率、帧率、码率、音频规格和字幕样式。

### 5.3 P2：后续探索

- 音色克隆和声音授权记录；
- 数字人和口型同步；
- 多平台发布和平台差异化版本；
- 团队协作、审批和素材权限；
- 更复杂的花字、模板、转场和自动包装；
- 账号实验自动归因和创作记忆推荐。

## 6. AI 的工作方式

AI 输出必须分成三类：

1. **建议**：可修改的文字、标签、选题、分镜和剪辑提案；
2. **结构化计划**：通过 schema 校验、可审阅、可版本化的对象；
3. **确定性执行**：只接受已冻结的合同，不在渲染过程中重新猜测。

AI 不直接拥有以下权力：

- 覆盖用户原项目；
- 删除原始素材；
- 绕过预算、授权和任务状态直接调用付费 Provider；
- 绕过命令注册表写任意时间线 JSON；
- 把未经证实的账号数据或事实写进“记忆”。

## 7. 成功指标

第一阶段不以“功能数量”为核心，而看生产结果：

- 从选题到第一版剪辑提案的时间；
- 分镜中已有素材的覆盖率；
- 补拍任务完成率；
- 自然语言素材搜索的首屏有效命中率；
- 用户接受 AI 剪辑提案的比例；
- 通用交付包进入其他编辑器的成功率，以及已验证剪映版本的实验导入成功率；
- 发布后复盘信息能否回到下一次选题和脚本；
- 本地项目恢复、迁移和素材重定位成功率。

所有指标都应绑定时间窗口、样本量和数据来源，不能用一次生成的主观感觉代替长期指标。

## 8. 版本推进

### 阶段 0：契约冻结

完成 PRD、领域模型、Provider/素材/交换格式契约、fixture 规则和评测任务。

### 阶段 1：本地创作闭环

完成项目、ThoughtPlan/脚本、分镜、手机拍摄包、多 Take 导入/选择、素材检索、AI 剪辑提案和 MP4/SRT/manifest/媒体包导出。

### 阶段 2：研究和外部 Provider

接入 TikHub、文本/视觉/ASR Provider、APIMart 异步任务和 FCPXML/OTIO。

### 阶段 3：剪映桥接和复盘

建立剪映版本矩阵、实验草稿适配器与 LossReport，并接入发布记录、数据快照和复盘记忆。

### 阶段 4：高级 AIGC

按实际用户痛点接入音色克隆、数字人、多平台分发和团队能力。

## 9. 风险与应对

| 风险 | 后果 | 处理方式 |
|---|---|---|
| 直接追赶剪映全部能力 | 资源被模板和特效吞噬，差异消失 | 先做内容理解、素材召回、补拍任务和桥接 |
| Provider 参数不断漂移 | UI、任务和项目文件不稳定 | 稳定 modelKey + 中性参数 + Provider mapping |
| 素材只有标签没有时间区间 | 搜到文件却无法直接剪 | 资产必须拆到可用镜头区间 |
| AI 黑盒直接出片 | 用户不信任，也无法修正 | Draft → Review → Freeze → Render |
| 临时 URL 当永久资产 | 过期后项目失效 | 下载回自有存储并记录来源和 hash |
| 账号数据没有证据 | 选题建议不可解释 | SourceEvidence + 时间窗口 + 原始响应 hash |
| 规则和代码事实不一致 | Agent 反复执行错误命令 | 命令经过验证后才能写入 AGENTS/README |

## 10. 当前默认决策

- 首个用户：个人或小团队口播创作者；
- 首个端：Windows/macOS 桌面端；
- 首个事实库：SQLite + 本地文件系统；
- 首个媒体底座：FFmpeg/ffprobe；
- 首个 AI 粗剪输出：MP4 + SRT/VTT + RenderManifest + 通用媒体交付包；
- 首个 Provider 顺序：本地文件/本地模型 → 通用文本/视觉/ASR → TikHub → APIMart；
- 首个稳定交换出口：FCPXML/OTIO/媒体包；剪映桥接是版本化实验能力，不是稳定协议；
- 首个许可证方向：核心 AGPL-3.0-only，公共 SDK/协议包 Apache-2.0。
