# 用户视角评审 · 切片 1 真实截图

日期:2026-08-19
评审对象:打包应用真实截图(`test:desktop:ui` 落盘的 workbench.png / ai-edit.png,1400×831 视口)
评审者:用户人设 agent(29 岁抖音口播博主,粉丝 2.1 万,每周 2-3 条,剪映熟练,首次打开本产品;未读任何设计文档,只看截图)
性质:事实 = 截图上确实存在;推断 = 用户人设的反应;处置 = 本文档拍板的去向。

## P0(会让用户关掉应用)

| # | 问题 | 处置 |
|---|------|------|
| P0-1 | **承诺当场跳票**:工作台卡片写「素材齐了,AI 已备好一版粗剪等你过目」,点「继续剪辑」进入后页面显示「还没有生成提案」,需手动再点生成。产品唯一卖点的第一次兑现即失信。 | 文案侧**本次已修**:editing 卡片改为「素材已导入,进去让 AI 出一版粗剪」,红点语义收回给「等你定」。根因侧留 **S2**:提案已持久化(`main.cjs:1425 saveEditProposal`),但 `ai-edit-workbench.tsx` 挂载时不回载(state 初始 null,仅查提交未知恢复项)——S2 加「挂载时回载最近提案」。 |
| P0-2 | **「继续剪辑」页面没有任何用户自己的东西**:无项目标题、无素材、无时间线、无粗剪画面,唯一标识是 UUID 徽标,用户无法确认进的是哪条片子。 | **S5 剪辑页换肤**(项目壳:← 工作台 + 项目名 + 阶段页签,见 `02-script.html` 头部),标题显示可在 S2 顺手带上(数据已在 workflow 里)。 |

## P1(困惑、试错后能继续)

| # | 问题 | 处置 |
|---|------|------|
| P1-1 | 剪辑页满屏工程师黑话:「本地可审计提案器」「Provider」「沿用同一份合同」「正式文件」「本地提案器」徽标。用户结论:「这软件不是给我做的」。 | S5 文案全部重写为用户语言;工程事实(本地执行、可追溯)转为一句人话或收进详情。 |
| P1-2 | 「粗剪」与「提案」两套词没打通,用户不确定是否同一物。 | 统一用户可见词为「粗剪」;「提案」只留在代码与文档。S5 执行,S2 新增文案先遵守。 |
| P1-3 | 空状态唯一动作「生成 AI 剪辑提案」是右上角小字,页面中央大字均不可点。 | S5:空状态改为页面中央主按钮。 |
| P1-4 | 剪辑页无返回、顶部导航无当前项高亮,用户不知身在何处。 | S5 项目壳解决(← 工作台);过渡期 S2 可先让「工作台」保持高亮。 |
| P1-5 | 首页无完整项目列表感:无封面帧、无时长、无最后修改时间,多项目时靠标题认。 | 事实澄清:工作台已渲染**全部**项目卡(listProjects 全量),缺的是封面帧/时长/时间元信息 → **S2** 卡片元信息。 |
| P1-6 | 导航词「记忆」猜不出含义,用户不敢点。 | **开放问题,需用户拍板**:候选如「创作记忆/风格库/我的偏好」;spec-02 待定项。 |
| P1-7 | 手机素材如何进电脑零指引,「拍好了就扔进来」跳过了最费劲的一步。 | **S3 正门范围**:导入引导需覆盖 AirDrop/数据线/局域网至少一条真实路径。 |
| P1-8 | 五段阶段条无标注,靠猜;黄色含义不明。 | 蓝本 P2 已记录;S2 做卡片时补悬停标注或首次引导。 |
| P1-9 | 生成提案前无预期管理:要多久、是否联网、花不花钱,一字未提。 | S5 文案;涉及付费 Provider 时按「等你定」报价惯例(蓝本已有样式)。 |

## P2(小别扭)

- UUID 徽标应换成项目名(S5);两页视觉气质割裂:黑白工具风 vs 米绿宋体(S5 换肤即消);英文小标 AI EDIT / HUMAN REVIEW / PROPOSAL(S5 去掉);「不会被假素材悄悄替代」自证清白反制造担忧(S5 文案);「剪掉磕巴和重来」的「重来」首读歧义,行话是「废条/重录」(蓝本文案复审);「等你过目」秘书腔(已随本次文案更换消失);「数据在本机」像按钮又不是按钮,且用户真正关心的是「草稿丢不丢」(蓝本 P2);「素材齐了」无依据入口(本次改为「素材已导入」,导入是事实);首页右侧大片留白像半成品(多项目后自然缓解;S2 空/满状态样张对账)。

## 用户人设的正面确认(一句带过)

「拍好了就扔进来」「AI 转写、剪掉磕巴和重来,直接给你一版粗剪」精准命中每周最烦的三件事;整页无运营位干扰,「像给干活的人用的」。方向保持。

## 与切片计划的关系

本评审不推翻切片 1 验收(门 1-5 均过);它把 S2/S5 的验收标准具体化了。S2 开工前把上表处置列并入 S2 计划的验收门。

# 第二轮 · 脚本页(S2)用户视角评审与处置

日期:2026-08-20。同一用户人设 agent 复审 S2 打包截图(script-page.png)。总评:「从文艺空壳进化成了能看懂的工作台」——时长预估、带理由的画面标注被点名是真本事;未再出现「想卸载」。

## 发现与处置

| 级别 | 问题 | 处置 |
|---|---|---|
| P0 | 「重新生成分镜」是全页唯一醒目按钮,且无「会否覆盖/能否撤销」说明,易被当「下一步」误点 | **已修**:有分镜时主按钮改为「去分镜看看拍法」,「重新生成分镜」降为安静文字按钮(title 注明会替换);脚本改动后闸门出记号红提示「重新生成会替换分镜和拍摄任务」(`storyboardFreshness` 纯函数,修订号对比) |
| P1 | 台词无可编辑暗示,「继续写脚本」进来找不到「写」 | **已修**:doc-note 改为「台词点进去直接改;右边的画面需求 AI 已标好,点一下换一档」;`.sp-words` 加 `cursor:text` |
| P1 | chip 点击行为(三档轮换)无预期 | **已修**:同上 doc-note「点一下换一档」;chip 视觉恢复药丸样(见下方 CSS 事故) |
| P1 | 改脚本后分镜是否过时不可知,「不敢改稿」 | **已修**:过时提示(同 P0 处置) |
| P1 | 「拍摄」页签虚线框与「拍摄任务已就位」语义打架 | **残留**,转拍摄环节切片:虚线是蓝本的 handoff 语义,需在拍摄卡/页签统一表达「不是页面但已就绪」 |
| P1 | 台词黄色高亮词规则成谜 | **部分缓解**:mark 加 title「AI 标的重点词,口播时加重语气」(悬停可见);完整图例转蓝本迭代 |
| P2 | 「已标好 3 段」歧义 / 「先按内容判断」悬空 / 说明重复两遍 | **已修**:闸门句改「3 段的画面需求已全部标好,不用再逐段确认。」,与 doc-note 分工不重复 |
| P2 | 结尾段缺失、加段/删段、AI 改写、字数显示、分镜预览 | **backlog**:段落增删是脚本页 v2 的必做项;AI 改写并入「让 AI 提结构建议」控件一起设计 |
| P2 | 「你承诺了『看见』」措辞、月牙图标含义 | why 行是种子数据非 UI 文案,真实数据来自 LLM 的 visualSuggestion;月牙=must 记号,转蓝本迭代 |

## 评审外的两个实证发现(本轮已修)

1. **生成分镜清空 emphasis/evidenceIds(存量数据 bug)**:`create-capture-workflow` 落新脚本修订时把两字段硬编码为空数组(main.cjs 原 1334 行),旧创作流每次生成分镜都在悄悄丢数据,S2 页面首次把它照出来(生成后高亮全灭)。修复:按调用方最新值/既有段落对齐保留;UI 冒烟加两道回归守卫(生成后 DOM mark 仍在 + SQLite emphasis 仍在)。
2. **作用域 button reset 压掉全部单类按钮样式**:`.sp-root button`(0,1,1)让 chip 边框、must 底色、cta 药丸全部失效,截图里 chip 是「灰色小字不像能点」——用户 agent 的该条 P1 实为此 bug。修复:reset 改 `:where(.sp-root) button`(0,0,1);shell.css 同款隐患一并修;规则入 `apps/desktop/renderer/AGENTS.md`(同类错误已犯两次)。

「目标 60s」为硬编码默认值、无域字段支撑,已改为无目标时只显示「预计 Ns」;目标时长字段何时进域模型,归脚本页 v2 讨论。

# 第三轮 · 剪辑页(S3)用户视角评审与处置

日期:2026-08-20。同一用户人设复审重建后的剪辑页(edit-page.png,粗剪回读态)。总评:「三轮里进步最大的一次……终于长成了剪辑工作台的骨架,黑话基本清干净了」;「在本机分析,不联网」被点名为全页最好的一句话;逐镜头采用/不用 + 默认帮选被确认为「方向就是我要的」。

## 发现与处置

| 级别 | 问题 | 处置 |
|---|---|---|
| P0 | **整页无画面/预览**:「改得了但看不见」,验收粗剪却一帧图像都没有 | **归 S4 应用内预览切片**(计划已列,本轮人设证据补强优先级);过渡态已有:证据行/候选行可点 → 系统播放器打开对应素材(最小可供性,蓝本验收 P1-3 的落地) |
| P1 | 三分钟口播只出 7s,页面零解释,用户以为素材被吞 | **已修**:头行改「粗剪 7s / 台词约 23s」对账(headSummary 带台词时长,单测覆盖) |
| P1 | 五行证据全是同一裸 UUID + 00:00,透明信息反而击穿信任 | **已修(显示层)**:素材名用文件 basename,查不到才截短 ID(assetDisplayName,单测);同 ID×5 是单素材冒烟的真实数据,多素材项目自然分散 |
| P1 | 补充画面行是「拍一个…」祈使句,像作业不像成片 | **归 S4**:根因在本地 fallback 提案器的 reason 文案(packages/agent-runtime),显示层不改写数据;S4 连同「你说了:」时态一并修提案器文案 |
| P1 | 下一步动作被裁在屏外 | **已修**:闸门/出片条 position:sticky 吸底常驻 |
| P1 | 「重新分析」无后果承诺,不敢点 | 部分缓解:按钮 title「会重新选一遍镜头,替换这版粗剪」;可见的「旧版保留/版本对比」归 S4 版本能力 |
| P2 | 时间码重叠(覆盖镜头)无「叠」的视觉暗示;「拍摄」页签虚线含义;时长直加对不上账 | 记档:覆盖行视觉暗示归 S4 预览;拍摄虚线归拍摄切片(第三次被点名,优先级上调) |

## 本轮实证补充(冒烟固化)

- 重开已渲染项目:粗剪镜头行 + 「已出片」条均回水合(`editPage:{restoredRows:5,restoredDone:true}`),卡片「去发布」与页面状态的承诺环闭合;
- 阶段推进:`stageProgression:{afterPropose:"editing",afterRender:"rendered",afterPublish:"published"}` 三点断言全绿,工作台卡片随真实阶段变化(已出片/去发布)。
