# 产品形状规格 02 · 从问题出发

取代:spec-01-creation-project.md
日期:2026-08-18
方法:先定用户的问题 → 只在「必须看着才能决定或行动」的地方放界面 → 再定交互与视觉

---

## 1. 用户的六个问题

一个口播创作者的完整循环:

| # | 问题(用他的话) | 性质 | 界面形态 |
|---|---|---|---|
| P1 | 这个选题值得拍吗? | 比较、看证据下注 | 决策面:机会卡 + 证据链 |
| P2 | 这话怎么说才像我? | 读和改 | 文档面:能改的稿子 |
| P3 | 这段话拿什么画面证明? | 看全貌,拍前发现窟窿 | 规划面:整条片子一眼看完 |
| P4 | 对着镜头讲出来 | **发生在手机上** | 桌面只有一张交接卡 |
| P5 | 这堆素材谁来剪? | 看片、说话、拍板 | 审片面:播放器+对话+收据 |
| P6 | 这条教会了我什么? | 确认一句话 | 轻:一个确认动作 |

两个由此推翻旧结构的结论:

- **「拍摄」在桌面不是一页。** 问题 P4 发生在手机上。桌面此刻只需要:二维码交接、`手机已拍 3/8` 的回流状态、素材回来时亮一下。提词器和逐镜清单在手机网页里(提词器是脚本的视图,不是第二份文本 —— Research-and-Architecture:278)。
- **「今天」不是一页。** 「接着干哪件」的答案就是项目列表本身,按下一步动作排序。单独的仪表盘是把排序问题做成了页面。

## 1.5 两扇门(最短价值路径,已入 AGENTS.md §3)

| 门 | 路径 | 首次价值 |
|---|---|---|
| **正门「拍好了就扔进来」** | 拖入素材 → 转写 + 删口头词/压停顿/剪重来 + 挑最完整 take + 字幕 → 看片答 0–2 问 → 导出 | **3 个动作,分钟级**;后端 e2e 已验证,无需脚本/分镜 |
| 侧门「从头做一条」 | 选题 → 脚本 → 分镜 → 拍摄 → 剪辑 → 发布 | 天级;差异化所在,给尝到甜头的人 |

短路引长路:快剪发现的缺口(「这段说了看见草稿,没有画面」)就是规划管线的入口 —— AI 顺势提出「下次拍之前先列拍摄清单」。上游阶段是增益不是门票。

**处理中不是页面**(页面存在性检验:该环节用户必做决策为 0)。进度以工作台那张 9:16 卡的状态呈现 —— 剪映同环节即如此(「分析中」进度 → 完成弹确认清单);完成后卡片亮起,点进去直接是剪辑面。转写文本作为信任证据,放在剪辑面的「文字稿」标签里,不单独成页。曾出过一版独立干活页(03-quickcut),已按此检验删除。

快剪项目的阶段条只显示真实存在的阶段(直接从「剪辑」开始),不显示被跳过的,免生迷惑。

## 2. 产品形状

```
工作台(项目列表,首页,回答「接着干哪件」)
 └─ 项目内三个阶段面:脚本 → 分镜 → 剪辑
     (拍摄 = 分镜与剪辑之间的交接卡,非页面)
选题(账号雷达作为其证据引擎收入其中)
素材库
记忆
设置(工具态)
```

导航四项 + 设置,比现行七标签少。

## 3. 每个面的签名交互(把大胆花在一处)

| 面 | 签名 | 依据 |
|---|---|---|
| 工作台 | **项目是一张竖片**:9:16 卡,标题像抖音封面题字;底部阶段条 + 下一步人话 | 项目终将成为一条竖屏视频,卡片即预告 |
| 脚本 | **旁注即合同,AI 起草、人改错**:每段右缘的画面需求由 AI 按内容预标,一键可改;只有拿不准的段落变成问题;强调词用记号笔高亮(对应 `emphasis` 字段) | must_show → 分镜必须配镜头 → 剪辑配不上停下来问 |
| 分镜 | **双轨胶片条**:A-roll 连续一条带,B-roll 覆盖浮其上,拍前看见窟窿 | 全市场空位:口播工具无分镜页,影视工具无提词 |
| 剪辑 | 对话 + 收据 + 版本(沿用 v9 交互模型,换视觉皮肤) | v9 交互经受住了推敲 |
| 记忆 | AI 提的记忆,不确认不生效 | AGENTS「可追溯」 |

## 3.5 决策预算(设计律,已入 AGENTS.md §3)

**必做决策数不得随内容长度线性增长。** 每页按真实规模推演:

| 面 | 真实规模 | 旧设计的决策数 | 现设计 |
|---|---|---|---|
| 脚本 | 1000 字 ≈ 17 段 | 17 次三态标注(闸门强制) | **0 必做**;AI 预标,1–3 个例外问题;右缘一键改 |
| 分镜 | ~20 镜 × 5 字段 | ≈100 次选择 | AI 出整版分镜;问题只来自缺口(must_show 找不到来源) |
| 拍摄 take | 8 镜 × 3 条 | 24 次比较 | AI 按中性事实预选,冲突或全差才问 |
| 剪辑 | 14 项操作 | (v3 前:逐条审批) | 已按此律重做:自动做 + 2 问 + 按类还原 |

配套规则:预填的默认值必须**一眼可辨、一键可改**;没答的问题按 AI 猜测走并标注,不阻塞下一步;「生成/继续」类按钮不设完成度闸门,只设诚实说明。

## 4. 勘误(相对 spec-01)

1. **覆盖规则**:`assertLayeredStoryboardCoverage` 的首要意图是 **A-roll 音轨连续无缺口**(每段有且只有一个 talking_head 主干,v4b:9),画面覆盖检查只是第三条断言。
2. **表达档案**:契约完整(四层 VoiceProfile、九步流水线、四栏对照审阅 UI,见 Script-Voice-and-Authenticity-Contract),实现为零且两份 schema 冲突。不是「后置不做」,是「先对账 schema,本期界面预留四栏对照的位置,AI 先出结构、人写句子」。
3. **提词器**:已有明确定义(脚本的视图;字号/速度/镜像/段落停顿/强调词/镜头提示;录后 ASR 对齐标漏讲改讲),不重新发明。跟随语速是行业共识(度加默认、开拍 AI 语速、Captions auto)。
4. **Take 判据**(spec-01 留白,现补上):不打分。给中性事实读数 —— 卡顿次数、静音比、语速漂移、脚本覆盖率;选择归人。零竞品给 take 打分,评分即「以通用流畅度伪造人味」。

## 5. 视觉语言(设计令牌)

**批判先行**:v1–v9 的暖纸 #f4f0e8 + Georgia/宋体 + 陶土橙,逐项命中 AI 默认模板第一名(frontend-design skill 校准段)。废弃。新方向从题材世界取材:字幕、提词器、场记板、9:16 竖框、时间码。

**色(5 值)**

| 名 | 值 | 用途 |
|---|---|---|
| 幕布 | `#F4F5F3` | 底。影棚无缝背景那种冷调灰白,不是奶油 |
| 石板 | `#22252B` | 主墨。场记板黑,冷 |
| 记号黄 | `#FFD84D` | **只做记号笔**:台词强调词高亮、当前阶段标记。不做按钮色 |
| 录制红 | `#E0442E` | 只表「进行中/等你定」:录制点、待决策 |
| 界线 | `#E3E4E1` | 分隔 |

**字(3 役)**

- 题字:PingFang SC / Noto Sans SC **重量 700–800**,收紧字距 —— 字幕卡的声音。克制使用:卡片题字、页级标题
- 正文:PingFang SC 400/500,14–15px;**台词正文 17px/行高 2** —— 它是要念出来的
- 数据:等宽,时间码、计数、金额

**这个产品的「文艺」是汉字排版的文艺,不是欧文衬线加奶油底的文艺。**

**冒的险**:记号黄作主强调(多数工具用蓝/绿/橙)。依据:创作者真的在台词上划重点;提词器文字传统就是黄的。
